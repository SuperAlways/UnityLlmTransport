## 5. 测试矩阵与判据

`Phase0Runner` 自动执行：

| 测试 | 期望 |
|---|---|
| `/sse` | Success / 200 / callbacks > 1 / first ≪ elapsed |
| `/sse-error` | ProtocolError / 500 / body=`{"error":"boom"}` |
| 错误端口 5198 | 502（系统代理）或 ConnectionError/0（直连）；必须记录实际 |
| `/sse-gzip` | Success / callbacks > 1；只看时序，不校验内容 |
| Abort（0.15s 后） | `Request aborted`；回调数在 1s 后不再增加 |
| 本地 ws | `type=Text bytes=10 text=echo:hello` |
| ws 错误端口 / 非 ws | `WebSocketException: Unable to connect`（可分类） |

**link.xml 对照（2021.3 已做，其他版本建议重复）**：

1. 把 `Assets/link.xml` 移出 `Assets`；
2. 重编 IL2CPP；
3. 运行：若卡死在首个 UWR 请求（`Curl error 42: Callback aborted`）→ link.xml 必要；
4. 移回 `Assets/link.xml`。

**系统代理注意**：

- 当前环境系统代理为 `127.0.0.1:7897`；
- 错误端口会返回 **502**，说明 UWR 走了系统代理；
- 要测直连，临时关闭系统代理后重跑该格（记录并恢复）；
- 显式代理只能 HttpClient，UWR 无 API。

**远程 wss / TLS / Close/Abort**（手动补充）：

- 远程 `wss://` 公共 echo 或自建 wss；失败按 TLS/代理/握手/超时归因；
- 本地 ws 第二次 `ReceiveAsync` 应收到 Close 帧；
- 测 `CloseAsync` vs `Abort()`；
- 自签 TLS 用 UWR `certificateHandler` / HttpClient handler。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `No valid Unity Editor license` / exit 198/199 | 无有效 license | Hub 登录 + Personal License；看 Licensing Client 日志 |
| `Found 0 entitlement groups` | 账号无 license | 重新登录/激活；必要时重装 Hub |
| `ToolchainNotFoundException` | 缺 VS C++ 工作负载 | VS Installer → Modify → Desktop development with C++ |
| 6.6 无 IL2CPP | 模块未装 | Hub Add modules；或本地 installer + UAC |
| 模块安装 404 | 中国 CDN 没有该版本模块 | 下载走代理 `--proxy http://127.0.0.1:7897` |
| UWR 错误端口 502 | 系统代理返回 | 关系统代理重测，或记录为代理行为 |
| 无 link.xml 卡死 | IL2CPP 剥离 handler 重写 | 保留 `link.xml` / `[Preserve]` |
| 服务端口占用 | 上一个 dotnet run 未退 | `netstat -ano | findstr 5199` → 结束进程 |
| 构建成功但行为旧 | Release 缓存/产物未覆盖 | 删 `Library`/`obj` 重编；核对产物 mtime |

## 11. Phase 2 harness（UWR 适配层）

> Phase 2 用 `unity/Phase2Harness`（15 场景 U1–U11）替代 Phase 0 的 spike runner。结果：`docs/spike/phase2-results.md`（2026-11-07 三版本 × Mono/IL2CPP 全 15/15）。

1. 建工程：`Unity.exe -createProject D:/UnitySpikes/Phase2-<ver> -batchmode -quit -logFile D:/UnitySpikes/create-phase2-<ver>.log`
2. 装配：`bash scripts/assemble-phase2-unity.sh D:/UnitySpikes/Phase2-<ver>`（每次改源后重跑；会重写 `Assets/UnityLlmTransport` + `Assets/link.xml`）
3. 构建：`Unity.exe -batchmode -quit -projectPath <proj> -executeMethod Phase2Build.BuildMono`（或 `BuildIl2cpp`）`-logFile D:/UnitySpikes/phase2-<ver>-<backend>.log`；判据 `PHASE2_BUILD <backend> Succeeded`
4. 运行：先起 `dotnet run -c Release --project spikes/SseTestServer`（5199），再跑 `D:/UnitySpikes/Builds/Phase2/<Application.unityVersion>/<backend>/Phase2.exe -logFile ...`；判据 = 日志 `PHASE2 <name>|OK|...`（15 行），摘录到 `phase2-<ver>-<backend>-results.txt`
5. `link.xml` 必须在 `Assets/link.xml`，目标程序集与承载 `StreamingDownloadHandler` 的 asmdef 同名（harness=Assembly-CSharp）
6. 进程纪律：服务用 PID 级 kill（`kill $SERVER_PID` / `taskkill //PID <pid>`），**禁止 `taskkill /IM dotnet.exe`**；跑玩家前 `netstat -ano | findstr 5199` 确认端口空闲
7. 2021.3 产物目录是 `Builds/Phase2/2021.3.45f1c2/`（`Application.unityVersion` 带 c2）；6.3/6.6 与编辑器版本号一致

## Phase 3 harness（HttpClient）

> 结果：`docs/spike/phase3-results.md`（2026-11-07 三版本 Mono H1–H9 = 12 判据 × 3 全过）。

1. `dotnet run -c Release --project spikes/Phase3TestServer`（HTTP 5201 / HTTPS 5233 / 代理 5234）

4. `Builds/Phase3/<Application.unityVersion>/mono/Phase3.exe`
5. 判据：`PHASE3 <name>|OK|`；本阶段只跑 Mono（IL2CPP 不声明）
6. 服务 PID 级 kill；禁止 mass-kill dotnet
7. 后台跑服务两个坑（Phase 2/3 实测）：`Console.ReadLine()` 在无 stdin 时立即返回导致进程自退——后台运行必须挂住 stdin（如 `< <(sleep N)`）；`dotnet run` 包一层父进程导致 kill 不达——直接跑 apphost exe（`spikes/Phase3TestServer/bin/Release/net10.0/Phase3TestServer.exe`），结束后 `netstat -ano` 拿 5201/5233/5234 LISTENING 的 PID，`taskkill //PID <pid> //T //F` 点杀并核验端口清零
