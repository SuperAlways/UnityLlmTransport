# 07 · 参考项目阅读与评估方法

> **目的**：在架构设计与阶段划分之前，按统一标准精读参考项目，产出可引用的证据与取舍结论。
> **原则**：切合度 > 许可证 > 质量 > 维护 > 依赖 > Stars；Stars 只是信号，不是标准。
> **日期**：2026-11-06

---

## 1. 评估维度与权重

| 维度 | 权重 | 看什么 |
|---|---:|---|
| 切合度 | 40% | Unity 2021 / netstandard2.1 / Mono/IL2CPP；真流式；取消；分层超时；代理/TLS；WebSocket；可测试 |
| 许可证/法律 | 15% | MIT/Apache；能否 vendor/复制；无 LICENSE 直接排除代码复用 |
| 代码质量/测试 | 20% | 单测、错误处理、状态机复杂度、文档 |
| 维护活跃度 | 10% | 最近 commit/issue/release |
| 依赖重量 | 10% | 引入包/UPM/原生插件；能否只取 1–2 个文件 |
| 流行度（Stars） | 5% | 只作参考，不作采用依据 |

评分 1–5，加权总分用于排序。**不因 star 高而采用，也不因 star 低而忽略。**

## 3. 阅读卡模板

每份笔记固定以下结构：

1. **基本信息**：repo / commit / 日期 / license / stars / 依赖 / 代码规模；
2. **架构地图**：分层、入口、关键文件；
3. **流式路径**：request → handler → decode → parse → event（file:line）；
4. **取消/超时**：机制、边界、残留回调；
5. **错误分类/重试**：状态码、错误体、退避；
6. **线程模型**：主线程/后台、UI 节流；
7. **测试**：单测、fixture、CI；
8. **可借鉴**：具体模式 + file:line；
9. **不可借鉴/风险**：许可证、依赖、平台限制；
10. **结论**：vendor / wrap / reference / avoid，附 1–5 分与理由。

证据标准：**源码 file:line > 官方文档 > 推测**；推测必须标注。

## 4. 子 agent 执行协议

- 只读参考仓库，不修改；只写自己的阅读卡到 `docs/08-阅读笔记/`；
- 每个子 agent 只负责一组仓库，不读无关目录；
- 输出 ≤ 2 页 Markdown；关键结论带 file:line；
- 不整段复制代码；许可证不明时明确写"只读，不复制"；
- 返回：状态、报告路径、3–5 条关键发现、切合度评分。

## 5. 综合与架构输入

阅读完成后汇总三张表：

1. **共识模式**：三家以上一致的（UWR handler、增量 UTF-8、行缓冲、Abort、节流、错误体）；
2. **分歧选择**：解析在主线程 vs 后台、HttpClient vs RawTcp、超时模型、WebSocket 实现；
3. **空白**：认证/签名钩子、分层超时公共件、主线程 dispatch、mock/录制回放、统一传输接口。

三张表 → `09-架构模式综合.md` → `10-开发阶段划分.md`。
