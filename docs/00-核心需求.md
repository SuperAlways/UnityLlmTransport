# 00 · 核心需求

> **状态**：立项需求 v0.1（2026-11-06），待 review。
> **项目**：UnityLlmTransport —— Unity 生态的独立 LLM 通讯组件。
> **一句话**：在 Unity + netstandard2.1 运行条件下（覆盖 AI mod 与原生 LLM/Agent 驱动的游戏两类宿主），给所有 LLM provider 提供一层可复用、可测试、可替换的通讯底座。
> **配套**：`01-Unity通讯问题陈述.md`（为什么）、`02-调研问题.md`（查什么）。

---

## 1. 背景与问题

- `.NET 8` 后端已有完整 `HttpClient` / pi.net，不需要再实现通讯层。
- Unity mod 运行在 **Mono/IL2CPP + 主线程 + 游戏生命周期** 下，不能升级 Unity，只能用 `netstandard2.1`。
- 现有 AI mod 各写一套传输：
  - Yaolao：UWR + `DownloadHandlerBuffer` → 假流式；
  - WorldTalk：UWR + `DownloadHandlerScript` → 真流式，但与业务耦合；
  - 江湖有灵：裸 `TcpClient + SslStream` + 手写 HTTP/1.1 → 真流式，但代理/HTTP2/重定向/连接池全自维护。
- 结果：**每个 mod 重复造传输层，质量、平台兼容、可测试性都不一致。**

---

## 2. 产品目标

> **做一层 Unity 生态可复用的 LLM 通讯组件，让 mod 开发者只关心"发什么、收什么"，不再关心 UWR/HttpClient/SSE/主线程/取消/代理。**

它不是 LLM 客户端，也不是 agent 框架；它只负责“通讯”。

**服务对象不限于 mod**：同一套组件既服务游戏内 AI mod（锁死 Unity 版本、无构建控制权），也服务原生 LLM/Agent 驱动的 Unity 游戏（可控制构建与生命周期）。两者共用 `Abstractions`/`Sse`；传输实现与宿主集成按需选配——原生游戏可注入自写 transport，也可直接复用我们的 UWR/HttpClient 适配器。

---

## 3. 目标用户与场景

| 用户 | 场景 |
|---|---|
| Unity AI mod 开发者 | 在游戏进程内调用 OpenAI/DeepSeek/Claude/Gemini 等接口，流式显示 |
| PiUnityAgent | 首个消费者：通过其**自有 Fetch 端口 + Host 适配器**消费本组件（B 方案）；`Ai` 不直接依赖 `Abstractions`，接缝见 `PiUnityAgent/docs/07-通讯层集成契约.md` |
| 其他 C# Unity 应用 | 需要 SSE/NDJSON 流式 HTTP，但不想自己处理 UWR 细节 |
| 原生 Unity AI 游戏开发者 | 在自研 Unity 游戏中接入 LLM/Agent 驱动；可复用我们的传输实现，或只取端口与 SSE、注入自己的 transport |

典型场景：

1. 流式对话：逐字显示 content / reasoning；
2. 流式工具调用：增量 JSON 参数；
3. 取消：玩家停止生成；
4. 代理/VPN：玩家网络环境；
5. 离线/本地模型：Ollama、vLLM、llama.cpp；
6. 长任务：Deferred / 长连接；
7. 无网测试：CI 注入 mock 传输。

## 4. 功能需求

### MUST（核心）

| ID | 需求 |
|---|---|
| R1 | **流式 HTTP 请求/响应**：method、URL、headers、body（string/bytes）；响应状态码、headers、增量响应体 |
| R2 | **真流式**：SSE 增量到达即交付；支持 chunked、多行 `data:`、`\r\n`、注释行、`[DONE]`、跨 chunk UTF-8 |
| R3 | **Unity 原生实现**：`UnityWebRequest + DownloadHandlerScript` 真流式；或可替换的等价实现 |
| R4 | **取消**：取消后尽快中止底层连接；不得只停止读取而让请求继续跑 |
| R5 | **超时分层**：连接超时、首字节超时、流空闲超时，分别可配 |
| R6 | **主线程交付**：网络/解析可在后台，事件/回调必须可安全 marshal 到 Unity 主线程 |
| R7 | **核心零 Unity 依赖**：Abstractions 程序集不引用 `UnityEngine`，可单测 |
| R8 | **可测试**：传输可注入 mock；CI 无网、无 key；支持错误/慢速/分块边界注入 |
| R9 | **错误分类**：网络、HTTP 非 2xx、协议/解析、空闲超时、取消；错误体可读 |
| R10 | **netstandard2.1**：不使用 .NET 6/7/8/9 专有 API；Unity 2021.3+ 可消费 |
| R10b | **Unity 版本兼容**：**2022.3.62f3c1（测试主基线 / Hub 安装；游戏实际 f2）**；兼容范围 **2021.3.45f1（最低边界）→ 6000.3.28f1（6.3 LTS）→ 6000.6.8f1（6.6）**；2022.3 补测中；版本差异只存在于 Unity 适配层，`PiUnityAgent.Ai` 不得判断 Unity 版本 |

### SHOULD（第二批）

| ID | 需求 |
|---|---|
| R11 | **HttpClient 传输**：桌面 Unity / .NET 8 后端可用，作为 UWR 的替代/对照 |
| R12 | **认证/签名钩子**：API Key、OAuth token、AWS SigV4、GCP ADC 的扩展点；不绑定 provider |
| R13 | **代理/TLS/重定向/压缩/连接池**：统一选项；实现不支持的项显式报错 |
| R14 | **NDJSON**：兼容非 SSE 的逐行 JSON 流 |
| R15 | **生命周期**：游戏暂停/切场景/退出/域重载时取消、无泄漏；多 mod 共存 |
| R16 | **可观测**：日志/指标钩子；API key 脱敏 |

### MAY（后续）

| ID | 需求 |
|---|---|
| R17 | **WebSocket 传输**（部分 provider/传输需要） |
| R18 | **RawTcp 兜底**（UWR/HttpClient 都不可用时） |
| R19 | **WebGL 支持**（fetch/XHR 流式） |
| R20 | **录制/回放**：把真实流量录成 fixture，CI 回放 |

---

## 5. 非功能需求

- **性能**：低分配、少拷贝；主线程回调不做重解析；避免每 chunk 刷 UI。
- **内存**：长连接/长响应不无限增长；有响应体/行长度上限。
- **安全**：默认证书校验；API key 不落日志；代理/自签场景显式配置。
- **兼容**：Unity 2021.3.45f1 / 6000.3.28f1 / 6000.6.8f1；Mono 优先，IL2CPP/AOT 可验证；不要求升级引擎。
- **可维护**：核心小、实现可替换、每个传输实现独立测试。
- **许可证**：MIT/Apache 类；尽量零/少第三方依赖。

## 6. 接口期望（概念，不是最终 API）

```csharp
public interface IStreamingHttpTransport
{
    Task<IStreamingHttpResponse> SendAsync(
        StreamingHttpRequest request,
        CancellationToken cancellationToken);
}

public sealed record StreamingHttpRequest
{
    public required string Method { get; init; }
    public required string Url { get; init; }
    public IReadOnlyDictionary<string, string> Headers { get; init; }
    public ReadOnlyMemory<byte> Body { get; init; }
}

public interface IStreamingHttpResponse
{
    int StatusCode { get; }
    IReadOnlyDictionary<string, string> Headers { get; }
    IAsyncEnumerable<ReadOnlyMemory<byte>> ReadBodyAsync(CancellationToken ct);
}
```

扩展点（形状待设计）：

- `IRequestAuthenticator` / `IRequestSigner`；
- `TransportCapabilities`（SSE/WebSocket/Proxy/HTTP2）；
- `TransportTimeoutOptions`（Connect/FirstByte/Idle）；
- `TransportError`（分类 + 可重试提示）；
- Unity 主线程 dispatcher / lifecycle token。

## 7. 验收标准（v1）

- [ ] 在目标 Unity 版本（Mono）里，对 OpenAI-compatible SSE 端点实现**真流式**：首字节到达即回调，不是整包；
- [ ] 取消后连接尽快中止，`CancellationToken` 语义明确；
- [ ] 空闲超时可触发；连接/首字节/空闲超时可分别配置；
- [ ] 代理与 TLS 可配置；错误分类可读；
- [ ] 核心程序集零 `UnityEngine` 引用；
- [ ] 用 mock transport 在 CI 无网跑通：文本、思考、工具调用、错误、取消、慢速分块；
- [ ] IL2CPP/AOT 冒烟（至少一个目标平台）；
- [ ] 不要求升级 Unity；`netstandard2.1` 编译通过。

---

## 8. 非目标

- 不做 provider 协议解析（OpenAI/Anthropic/Gemini JSON 映射属于 PiUnityAgent.Ai）；
- 不做 agent loop / 工具执行；
- 不做 UI；
- 不做完整 HTTP 客户端/服务端框架；
- 不做 OAuth 登录 UI；
- 不做非 Unity 引擎（Unreal/Godot/自研 C++）的适配——那属于原版 pi / pi.net 或新 transport 的范围；
- 不把“整包缓冲”称为流式；
- 不默认引入原生插件/闭源 SDK。

---

## 9. 优先级

### P0（MVP）

- Abstractions；
- UWR + `DownloadHandlerScript` 流式传输；
- SSE 增量解析器；
- 主线程分发 + 生命周期取消；
- mock transport + 基础测试。

### P1

- HttpClient 传输；
- 认证/签名钩子；
- 代理/TLS/超时/错误分类；
- 录制/回放基础。

### P2

- WebSocket；
- RawTcp 兜底；
- WebGL；
- 更完整的可观测性。
