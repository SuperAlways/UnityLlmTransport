# 05 · 版本与兼容基线

> **目的**：把“对齐哪个 pi、跑在哪个 Unity/.NET、支持到什么程度”钉死，避免开发中漂移。
> **日期**：2026-11-06

---

## 1. 上游对齐版本

| 角色 | 版本 | 用途 |
|---|---|---|
| **pi（原版）** | `v1.5.0` / `f9a263655` | 行为真相源：协议、能力面、事件语义 |
| **pi.net** | `main` / `2d6757b`（net9.0;net10.0） | 只作 C# 语言映射参考；**不作运行时基线** |
| **UnityLlmTransport** | 独立项目，版本从 `0.x` 起 | 通讯底座 |

> pi.net 目标 net9/10，使用了 `Task.WaitAsync`、`Stopwatch.GetElapsedTime`、`System.Threading.Lock` 等；这些在 Unity 2021 + netstandard2.1 下不可用。冲突时以 pi（原版）语义为准，C# 写法参考 pi.net，但不复制其运行时假设。

---

## 2. 运行时基线

| 项 | 决定 | 说明 |
|---|---|---|
| 语言/框架 | **C# `netstandard2.1`** | Unity 2021.2+ 可消费；测试工程 `net10.0` |
| Unity 版本 | **2021.2+；以 2021.3 LTS 为文档/验证基准** | 实际版本由目标游戏锁定；不要求升级 |
| 脚本运行时 | **Mono 优先**；IL2CPP 需冒烟 | IL2CPP 需 `link.xml`/`[Preserve]` 保护 handler 重写 |
| 平台 | **Windows 桌面优先** | macOS/Linux 未验证；WebGL 放 M2 |
| WebGL | **M1 不支持** | 无 HttpClient/SslStream/线程；M2 用 `.jslib` + fetch |
| HTTP/2 | **M1 不承诺** | Unity 2021 无；桌面 HttpClient 可选 |
| 代理 | UWR 仅系统代理；显式代理走 HttpClient | 2021.3 无显式 proxy API |
| 取消 | `CancellationToken` → `Abort()` | 取消必须中止连接 |
| 超时 | 首字节 / 空闲两个看门狗 | 不依赖 `UnityWebRequest.timeout` |
| 测试 | 纯 .NET 单测 + mock transport | 无 Unity 依赖的 Abstractions 必须可单测 |

## 3. 兼容矩阵

| 能力 | Unity 2021.3 Mono | IL2CPP | WebGL | .NET 8 后端 |
|---|---|---|---|---|
| UWR + DownloadHandlerScript | ✅ | ✅（需 link.xml） | ✅（UWR） | N/A |
| HttpClient | ⚠️ 需实机验证 | ⚠️ 需验证 | ❌ | ✅ |
| RawTcp/SslStream | ✅ | ✅ | ❌ | ✅ |
| SSE 增量 | ✅ | ✅ | ✅（fetch） | ✅ |
| WebSocket | ⚠️ 本地 `ws://` 已验证（`PerceptionWsClient`）；`wss` 未验证 | ⚠️ 未验证 | ⚠️ 需 `.jslib` | ✅ |
| 显式代理 | ❌（仅系统） | ❌ | 浏览器 | ✅ |
| 自签/企业证书 | ✅ certificateHandler | ✅ | 浏览器 | ✅ |
| HTTP/2 | ❌ | ❌ | 浏览器 | ✅ |
| 主线程回调 | ✅ 需 dispatch | ✅ | ✅ | N/A |
| 生命周期取消 | ✅ 需接入 | ✅ | ✅ | N/A |

> ✅ 支持；⚠️ 需实机验证/有条件；❌ 不支持。
> “支持”= 能编译 + 单测 + 目标平台实机冒烟；不是“理论上可用”。

## 4. 依赖与许可证策略

- **核心 Abstractions**：零 `UnityEngine`、零网络实现依赖；
- **SSE 解析器**：优先 vendor `System.Net.ServerSentEvents`（MIT）的 `netstandard2.0` 源码；避免依赖 .NET 9+ 包版本；
- **System.Memory / IAsyncEnumerable**：Unity 2021 自带/兼容性需编译验证；冲突时 vendor 或降级；
- **第三方库**：MIT/Apache-2.0；不引入原生插件/闭源 SDK；
- **mikito 示例**：无 LICENSE，**不可复制代码**；
- **LaunchDarkly.EventSource**：Apache-2.0，可选参考/桌面实现，不放进 Unity 核心；
- **com.openai.unity**：MIT，但 6 个 UPM 依赖，只参考不依赖。

## 5. 包与命名（建议）

```
UnityLlmTransport.Abstractions   // 纯接口/DTO，netstandard2.1
UnityLlmTransport.HttpClient     // HttpClient 实现（桌面/后端）
UnityLlmTransport.UnityWebRequest// UWR 实现（Unity 2021.3+）
UnityLlmTransport.RawTcp         // 可选兜底
UnityLlmTransport.Hosts.Unity    // 主线程 dispatch/生命周期
```

- 仓库/显示名：`UnityLlmTransport`；
- NuGet/UPM 包 ID 建议加组织前缀（如 `YourOrg.UnityLlmTransport`），避免与官方混淆；
- 版本：`0.x` 阶段；接口稳定后再考虑 `1.0`。

## 6. 支持定义

一个平台/传输算“支持”，必须同时满足：

1. `netstandard2.1` 编译 0 错误；
2. 核心单测全绿（SSE、解码、超时、取消、错误分类）；
3. 目标平台实机冒烟：真流式、取消、首字节/空闲超时、错误分类；
4. IL2CPP（如声明支持）额外冒烟：handler 重写未被剥离；
5. 有 mock/录制回放回归。

否则只能标“实验/未验证”，不能写“支持”。

## 7. 待定决策

1. **Unity 精确版本**：以目标游戏实际版本为准；文档按 2021.3 LTS，若游戏是 2021.2 需单独验证；
2. **WebGL**：M2 是否投入；
3. **HttpClient 传输**：M1 是否提供，还是只做 UWR；
4. **RawTcp**：是否保留兜底；
5. **WebSocket**：按 Codex 等 provider 需求再上；
6. **认证范围**：M1 只做 API Key 注入，OAuth/SigV4 后置；
7. **包管理**：UPM 包 vs NuGet vs 源码嵌入；
8. **命名**：`UnityLlmTransport` 的商标/官方混淆风险评估。
