## 1. 设计原则

1. **传输只吐字节**：不判断 `[DONE]`、不拼 JSON、不做 provider 语义。
2. **Abstractions 零 Unity 依赖**：核心可纯 .NET 单测；Unity 差异关在实现/Host。
3. **取消 = 中止连接**：`CancellationToken` 必须桥接到 `Abort()`，不是停止读取。
4. **超时分层的公共件**：连接/首字节/空闲三个看门狗，不依赖 `UnityWebRequest.timeout`。
5. **认证/签名是钩子**：API Key/OAuth/SigV4/ADC 不进入传输实现。
6. **可替换**：UWR / HttpClient / RawTcp / WebSocket 都是实现，不是接口。
7. **可测试**：mock transport、录制回放、错误注入是一等能力。
8. **不复制无许可证代码**：WorldTalk / 江湖有灵 / Yaolao / mikito 只参考模式。

## 3. 核心接口

### 3.1 传输

```csharp
public interface IStreamingHttpTransport
{
    TransportCapabilities Capabilities { get; }

    Task<ITransportSession> OpenAsync(
        TransportRequest request,
        TransportOptions options,
        CancellationToken cancellationToken);
}

public sealed record TransportRequest(
    string Method,
    string Url,
    TransportHeaders Headers,
    ReadOnlyMemory<byte> Body)
{
    /// <summary>可选：大请求（图片/多模态）用工厂重建流；设置后忽略 Body。
    /// 必须是可重放的（重试会再次调用），P2 能力。</summary>
    public Func<CancellationToken, Task<Stream>>? BodyFactory { get; init; }
}

/// <summary>HTTP headers：名称大小写不敏感；请求中 value=null 表示“抑制默认头”。</summary>
public sealed class TransportHeaders : Dictionary<string, string?>
{
    public TransportHeaders() : base(StringComparer.OrdinalIgnoreCase) { }
    public TransportHeaders(IDictionary<string, string?> values)
        : base(values, StringComparer.OrdinalIgnoreCase) { }
}

public enum ProxyMode { None, System, Explicit }

public sealed record ProxyOptions
{
    public ProxyMode Mode { get; init; } = ProxyMode.System;
    public string? Url { get; init; }
    public NetworkCredential? Credentials { get; init; }
}

public sealed record TlsOptions
{
    public bool ValidateCertificate { get; init; } = true;
    public X509Certificate2? ClientCertificate { get; init; }
    public IReadOnlyList<X509Certificate2>? CustomRoots { get; init; }
    public SslProtocols? Protocols { get; init; }
}

public sealed record TransportOptions
{
    public TimeSpan? ConnectTimeout { get; init; }
    public TimeSpan? FirstByteTimeout { get; init; }
    public TimeSpan? IdleTimeout { get; init; }
    public int? MaxResponseBytes { get; init; }
    public ProxyOptions? Proxy { get; init; }
    public TlsOptions? Tls { get; init; }

    // 传输选择与 pi 选项映射（详见 §8.2）
    public TransportKind Kind { get; init; } = TransportKind.Auto;
    public TimeSpan? WebSocketConnectTimeout { get; init; }
    public IdentityOptions? Identity { get; init; }
    public IReadOnlyDictionary<string, string>? Env { get; init; }
    public IReadOnlyDictionary<string, object?>? Metadata { get; init; }
    public TransportCacheRetention? CacheRetention { get; init; }
    public string? SessionId { get; init; }
    public RedirectPolicy Redirects { get; init; } = RedirectPolicy.Follow;
    public bool Decompress { get; init; } = true;
}

public interface ITransportSession : IAsyncDisposable
{
    int StatusCode { get; }
    TransportHeaders Headers { get; }

    /// <summary>响应体；任意状态码都可读（错误体也是 Body）。</summary>
    Stream Body { get; }

    /// <summary>立即中止底层连接；幂等。</summary>
    void Abort();
}
```

约定：

- `OpenAsync` **只对“响应头之前”的失败抛 `TransportException`**（连接/TLS/代理/连接超时）；
- 一旦拿到 HTTP 状态（包括 4xx/5xx），返回 `ITransportSession`，由上层决定读错误体；
- `Body` 对流式响应是增量 `Stream`；对非流式响应可读完；
- `Abort()` 必须在中止后让 `Body.ReadAsync` 尽快结束（完成或异常）。

### 3.2 能力

```csharp
[Flags]
public enum TransportCapabilities
{
    None = 0,
    StreamingBody = 1 << 0,
    WebSocket = 1 << 1,
    ExplicitProxy = 1 << 2,
    Http2 = 1 << 3,
    TlsCertificateHandler = 1 << 4,
    Compression = 1 << 5,
    RequestFinalizer = 1 << 6,     // 能在最终 header 上签名；UWR 若发送后追加头则不可用
    SystemProxy = 1 << 7,
    ProxyAuthentication = 1 << 8,
    WebSocketOverTls = 1 << 9,
}
```

能力用于上层选择实现/回退；**不支持的能力必须显式报错，不能静默忽略**。

### 3.3 错误

```csharp
public enum TransportErrorKind
{
    Connect,          // 连接失败/DNS/TCP
    Tls,              // 证书/握手
    Proxy,            // 代理失败
    HttpStatus,       // 非 2xx（可选携带状态码/headers/错误体）
    Handshake,        // WebSocket 握手失败（401/403/404/426/Origin/SubProtocol）
    Protocol,         // 响应头/分块/SSE 协议错误
    FirstByteTimeout,
    IdleTimeout,
    Cancelled,
    Aborted,
    Overflow,         // 响应体/缓冲超限
    Unsupported,      // 能力不支持（如 UWR 显式代理）
}

public sealed class TransportException : Exception
{
    public TransportErrorKind Kind { get; }
    public int? StatusCode { get; }
    public TransportHeaders? Headers { get; }
    public string? ErrorBody { get; }
    public bool IsRetryable { get; }
}
```

- `IsRetryable` 只做**分类提示**（网络/408/409/429/5xx）；是否重试由上层策略决定。
- 流已开始后不再重试；避免重复内容/重复计费。

### 3.4 超时/中间件装饰器

```csharp
public sealed class TimeoutTransport : IStreamingHttpTransport
{
    // 包装任意 transport；ConnectTimeout 透传，FirstByte/Idle 由 TimeoutStream 执行
}

public sealed class MiddlewareTransport : IStreamingHttpTransport
{
    // 依次应用 IRequestMiddleware（认证/签名/日志）
}

public interface IRequestMiddleware
{
    ValueTask<TransportRequest> InvokeAsync(
        TransportRequest request,
        CancellationToken cancellationToken);
}
```

- `ConnectTimeout` 由具体 transport 实现（UWR/HttpClient）；
- `FirstByteTimeout` / `IdleTimeout` 由 `TimeoutStream` 包装 `Body`：
  - 第一次读到字节前：首字节看门狗；
  - 每次读到字节后重置：空闲看门狗；
  - 超时 → `session.Abort()` → `TransportException(FirstByteTimeout/IdleTimeout)`。
- 所有装饰器可组合：`new TimeoutTransport(new MiddlewareTransport(inner, auth))`。

### 3.5 认证/签名

- `IRequestMiddleware` 负责：API Key header、OAuth token header、SigV4/ADC/Azure AD 签名；
- 传输层**不存储凭据、不刷新 token**；
- 凭据/刷新/登录属于独立认证模块（PiUnityAgent.Ai 或上层）；
- 中间件返回新的 `TransportRequest`（不可变），便于测试/日志。

## 4. 数据流

```
Provider adapter
  → 构造 TransportRequest（URL/headers/body）
  → MiddlewareTransport（认证/签名）
  → TimeoutTransport（连接/首字节/空闲）
  → UWR / HttpClient / RawTcp
  → ITransportSession（status/headers/Body）
  → SseParser（SseItem 流）
  → provider 协议聚合（content/reasoning/tool_calls/usage）
  → PiUnityAgent S2 事件
```

- **Body 是 `Stream`**：直接喂 `SseParser.Create(session.Body)`，避免再发明一套字节抽象；
- SseParser 负责 UTF-8 增量解码、跨 chunk 行缓冲、SSE 字段语义；
- provider adapter 负责 JSON 语义、`[DONE]`、tool_calls 聚合、usage、stopReason。

## 5. UWR 传输（Unity 主路径）

### 5.1 结构

```
UnityWebRequestTransport : IStreamingHttpTransport
  ├─ UnityWebRequestRunner（Host 提供，协程/主线程）
  └─ OpenAsync:
       request = new UnityWebRequest(url, method)
       request.uploadHandler = new UploadHandlerRaw(body)
       request.downloadHandler = new StreamingDownloadHandler(channel)
       request.timeout = 0
       request.SetRequestHeader(...)
       await runner.SendAsync(request, ct)
       if pre-header failure → TransportException
       return UnityWebRequestSession(request, channel.Reader)
```

### 5.2 `StreamingDownloadHandler`

```csharp
sealed class StreamingDownloadHandler : DownloadHandlerScript
{
    private readonly Channel<byte[]> _channel; // bounded
    protected override bool ReceiveData(byte[] data, int length)
    {
        // 仅拷贝入队，不做解析
        // TryWrite 失败 → 标记 Overflow → request.Abort()
        return true;
    }
    protected override void CompleteContent() { _channel.Writer.TryComplete(); }
}
```

- `ReceiveData` 在主线程；**只入队**，不做 UTF-8/SSE/JSON；
- 队列有界（如 1–4 MB）；溢出 → `Overflow` + `Abort()`；
- `CompleteContent` 完成 channel；错误路径以 `TransportException` 完成；
- `Abort()` 后残留回调：状态位丢弃；
- IL2CPP：`link.xml` / `[Preserve]` 保住 `ReceiveData`/`CompleteContent` 重写。

### 5.3 `ChannelReadStream`

- 把 `ChannelReader<byte[]>` 适配成 `Stream`；
- `ReadAsync(Memory<byte>, ct)` 供 SseParser 使用；
- `Read` 同步版本用于兼容；
- 取消/Abort 时完成/异常化。

### 5.4 协程桥

- `UnityWebRequest.SendWebRequest()` 返回 `UnityWebRequestAsyncOperation`；
- Host 提供 `IUnityWebRequestRunner`（MonoBehaviour 协程）把 operation 桥成 `Task`；
- 取消 → `request.Abort()`；取消异常归一为 `TransportException(Cancelled)`。

### 5.5 响应头/错误体

- `OpenAsync` 成功后从 `request.GetResponseHeaders()` / `responseCode` 构建会话；
- 任意状态码都返回会话；provider 可读 `Body` 作为错误体；
- 连接错误：`request.result == ConnectionError` → `TransportException(Connect)`，不要只看 `responseCode == 0`。

## 6. HttpClient 传输（桌面/后端/显式代理）

- `HttpClientTransport : IStreamingHttpTransport`；
- `HttpCompletionOption.ResponseHeadersRead`；
- `Body = await response.Content.ReadAsStreamAsync()`；
- 取消 token 透传；`ConnectTimeout` 由 handler/timeout 实现；
- 显式代理/自签/HTTP2 由注入的 `HttpClientHandler` 配置；
- 非 2xx 返回会话，错误体可读；
- 作为 UWR 的替代/对照，不作为 Unity 核心依赖。

## 7. 线程与生命周期

- `ReceiveData`：Unity 主线程，只入队；
- SseParser/协议聚合：后台线程/`Task`；不调用 Unity API；
- UI 事件：`Hosts.Unity` 提供 `IMainThreadDispatcher.Post(Action)`；
- 生命周期：`CancellationToken` 由 Host 绑定游戏/域/场景；会话 `DisposeAsync` 时 `Abort()`；
- 禁止全局静态单例；每个请求独立会话；
- 多 mod：不使用固定端口/全局事件总线；命名空间隔离。

### 7.1 Unity 版本适配（2021.3 / 6.3 / 6.6）

**目标版本**：

| 版本 | changeset | 角色 |
|---|---|---|
| 2021.3.45f1 | `0da89fac8e79` | 主目标 / 游戏锁定基线 |
| 6000.3.28f1（6.3 LTS） | `8f082d2fe476` | HTTP/2 前向验证 |
| 6000.6.8f1（6.6） | `237b6593792b` | 最新运行时验证 |

**硬规则**：

1. **版本差异只存在于 Unity 适配层**：`Abstractions` 与 `PiUnityAgent.Ai` 不出现 `#if UNITY_*`、`Application.unityVersion`、`UnityEngine`。
2. **按最低公共 API 编译**：库按 Unity 2021.3 + netstandard2.1 + C# 9 可编译的 API 写；6.3/6.6 新 API 只在 Unity 适配层、带 fallback。
3. **用能力而不是版本**：`TransportCapabilities`（`Http2`/`SystemProxy`/`ExplicitProxy`/`WebSocketOverTls`）由适配器运行时设置；上层只读能力。
4. **行为归一化**：
   - UWR 统一 `timeout=0` + 首字节/空闲看门狗；
   - `responseCode=0` 统一先看 `result`；
   - TLS/代理错误统一归为 `Tls`/`Proxy`；
   - `ReceiveData` 统一只入队，不解析。
5. **回退链**：显式代理走 HttpClient；WebSocket 不可用报 `Unsupported`；HTTP/2 不可用自动 HTTP/1.1，不要求上层判断。
6. **测试矩阵**：三个版本各跑同一组 spike（UWR/代理/TLS/WS/IL2CPP）；差异只更新能力矩阵，不改 PiUnityAgent.Ai。

**版本差异表**：

| 能力 | 2021.3.45f1 | 6.3.28f1 | 6.6.8f1 | 归一化 |
|---|---|---|---|---|
| HTTP | HTTP/1.1 | UWR 可能 HTTP/2 | 可能 HTTP/2 | `Http2` 能力 |
| TLS/网络栈 | 较旧 | 更新 | 更新 | 错误分类 |
| UWR 流式 | DownloadHandlerScript | 同左 | 同左 | 同一 adapter |
| WebSocket | ClientWebSocket | 同左 | 同左 | `IWebSocketTransport` |
| IL2CPP | link.xml | 需验证 | 需验证 | 同一 link.xml |
| C#/运行时 | C#9/netstandard2.1 | 更新 | 更新 | 仍按 C#9 编译 |

### 8.2 pi 选项 → TransportOptions 映射

| pi 选项 | 传输层承载 |
|---|---|
| `signal` | `CancellationToken`（桥接 `Abort()`） |
| `fetch` | `IStreamingHttpTransport` 注入 |
| `headers` | `TransportRequest.Headers` |
| `identity` | `TransportOptions.Identity` |
| `env` | `TransportOptions.Env` |
| `onPayload` | `IRequestMiddleware`（发送前改写请求体） |
| `onResponse` | `ITransportObserver.OnResponseAsync` |
| `onProviderStreamEvent` | `ITransportObserver.OnBodyChunkAsync` + Sse 解析后的 tap |
| `timeoutMs` | 映射到 `ConnectTimeout` + `IdleTimeout`；**不设整请求硬超时** |
| `maxRetries` / `maxRetryDelayMs` | `RetryOptions` |
| `transport` | `TransportKind`（Auto/Sse/WebSocket/WebSocketCached） |
| `websocketConnectTimeoutMs` | `TransportOptions.WebSocketConnectTimeout` |
| `cacheRetention` / `sessionId` | `TransportOptions.CacheRetention` / `SessionId` |
| `telemetry` | `ITransportObserver` / Telemetry 钩子 |
| `deferred` | `DeferredOptions`（长轮询/再次请求），见 §8.6 |
| `toolChoice` / `reasoning` | **协议层**，不进传输层 |

> `timeoutMs` 在 pi 里是“请求超时”；对 SSE 长连接，整请求硬超时会误杀。传输层把它拆成连接/空闲两个看门狗，并在文档中明确这一映射偏差。

### 8.3 WebSocket 传输形状

pi 的 `openai-codex-responses.ts` 使用 WebSocket（`transport=sse|websocket|websocket-cached|auto`）。因此传输层不能只有 SSE。

```csharp
public interface IWebSocketTransport
{
    TransportCapabilities Capabilities { get; }

    Task<IWebSocketSession> ConnectAsync(
        WebSocketRequest request,
        WebSocketOptions options,
        CancellationToken cancellationToken);
}

public sealed record WebSocketRequest(
    string Url,
    TransportHeaders Headers);

public sealed record WebSocketOptions
{
    public TimeSpan? ConnectTimeout { get; init; }
    public TimeSpan? IdleTimeout { get; init; }
    public TimeSpan? KeepAliveInterval { get; init; }
    public int? MaxMessageBytes { get; init; }
    public ProxyOptions? Proxy { get; init; }
    public TlsOptions? Tls { get; init; }
    public TransportHeaders? Headers { get; init; }
    public string? SubProtocol { get; init; }
    public string? Origin { get; init; }
    public RedirectPolicy Redirects { get; init; } = RedirectPolicy.Error;
}

public enum WebSocketMessageType { Text, Binary, Close }

public sealed record WebSocketMessage(
    WebSocketMessageType Type,
    ReadOnlyMemory<byte> Payload,
    bool EndOfMessage,
    WebSocketCloseStatus? CloseStatus = null);

public interface IWebSocketSession : IAsyncDisposable
{
    WebSocketState State { get; }
    Task SendAsync(WebSocketMessage message, CancellationToken ct);
    IAsyncEnumerable<WebSocketMessage> ReceiveAsync(CancellationToken ct);
    Task CloseAsync(WebSocketCloseStatus status, string? description, CancellationToken ct);
    void Abort();
}
```

**参考实证**：`说书人测试/mods/StorytellerPerception/src/Frontend/PerceptionWsClient.cs` 在 netstandard2.1 Unity 前端使用 `System.Net.WebSockets.ClientWebSocket` 连接本地 `ws://127.0.0.1:8000/ws`，包含：
- `ConnectAsync` + 身份帧；
- 有界发送队列（`MaxQueued=2000`，满丢最旧）；
- 重连锁存 + 连接超时恢复；
- 收信循环 + `Close` 处理；
- 发送/接收失败后触发重连。

**结论**：`ClientWebSocket` 在桌面 Unity Mono + netstandard2.1 下可用（至少 `ws://` 本地）。但以下未验证：
- `wss://`（TLS/证书）；
- 代理；
- IL2CPP；
- WebGL（`ClientWebSocket` 不可用，需 `.jslib`）；
- Unity 主线程 marshal（其 `Debug.Log` 在后台线程调用，需避免依赖 Unity API）。

### 本地 vs 远程：不能把 `ws://127.0.0.1` 当远程证据

| 维度 | 本地 `ws://127.0.0.1` | 远程 `wss://api.example.com` |
|---|---|---|
| DNS | 无 | DNS/IPv6/防火墙 |
| TCP | 回环 | NAT/企业网/超时 |
| TLS | 无 | 握手/证书/SNI/密码套件 |
| 代理 | 绕过 | 系统代理/显式代理/CONNECT |
| 握手 | 宽松 | 401/403/404/426、Origin、SubProtocol |
| 心跳 | 不必要 | idle timeout → 需要 ping/pong/keepalive |
| 重定向 | 不涉及 | WebSocket 不自动跟 301/302 |
| 稳定性 | 高 | 断线/重连/半开连接 |

**因此：本地 ws 可用，不代表远程 wss 可用。** 支持等级必须分开声明：

- `ws://` 本地：已由 `PerceptionWsClient` 证明（桌面 Mono）；
- `wss://` 远程：需要单独 spike（TLS/代理/握手/keepalive），未验证前标“实验”；
- IL2CPP/WebGL：单独验证。

WebSocket 行为放阶段 5；**接口形状现在保留**。

### 8.4 重试管线

pi 有 `maxRetries`、`maxRetryDelayMs`、`provider-retry.ts`。传输层需要可复用的重试装饰器，而不是每个 provider 各写一套。

```csharp
public sealed record RetryOptions
{
    public int MaxRetries { get; init; } = 2;
    public TimeSpan MaxRetryDelay { get; init; } = TimeSpan.FromSeconds(60);
    public TimeSpan BaseDelay { get; init; } = TimeSpan.FromMilliseconds(500);
}

public interface IRetryPolicy
{
    bool ShouldRetry(TransportException error, int attempt);
    TimeSpan GetDelay(TransportException error, int attempt);
}

public interface IAuthRefreshHandler
{
    Task<bool> RefreshAsync(CancellationToken ct);
}

public sealed class RetryTransport : IStreamingHttpTransport
{
    // 只在“首字节之前”重试；流已开始后绝不重试
    // 401 可先 IAuthRefreshHandler.RefreshAsync 再重试一次
}
```

规则：

- 可重试：网络、408、409、429、5xx、`x-should-retry: true`；
- 不重试：401/403/400（除非 refresh 后重试）、流已开始后的任何错误；
- 尊重 `Retry-After` / `retry-after-ms`，超过 `MaxRetryDelay` 直接失败；
- 指数退避 + 抖动；可取消；
- 重试单位是**整个请求**，必须保证没有已消费的响应体（首字节前）。

### 8.5 可观测钩子

pi 的 `onResponse`、`onProviderStreamEvent`、`telemetry` 需要挂点，否则无法实现等价能力。

```csharp
public sealed record TransportResponseInfo(
    int StatusCode,
    TransportHeaders Headers);

public interface ITransportObserver
{
```

### 8.7 签名最终化与传输选择

### 签名最终化

SigV4/ADC/Azure AD 签的是**最终发送的请求**。如果中间件先签名、传输层再添加 `Host`/`Content-Length`/`User-Agent`，签名会失效。

```csharp
public interface ITransportRequestFinalizer
{
    ValueTask<TransportRequest> FinalizeAsync(
        TransportRequest request,
        CancellationToken ct);
}
```

强制顺序：

```
transport 构造最终请求（含 Host/Content-Length/默认头）
  → finalizer（签名/最终 header）
  → 发送
  → 发送后不得再改 header
```

- SigV4 只应在**能控制最终 header 的传输**上启用（HttpClient/RawTcp）；UWR 若在发送后追加 header，必须禁用签名或改用 HttpClient。
- 能力声明 `TransportCapabilities` 增加 `RequestFinalizer` 标志，上层据此选实现。

### 传输选择

```csharp
public enum TransportKind { Auto, Sse, WebSocket, WebSocketCached }

public sealed record TransportSelectionContext(
    string Api,
    string Provider,
    string BaseUrl,
    TransportKind Kind);

public sealed record TransportSelection(
    IStreamingHttpTransport? Http,
    IWebSocketTransport? WebSocket);

public interface ITransportSelector
{
    TransportSelection Select(TransportSelectionContext context);
}

public sealed record TransportFallbackPolicy(
    IReadOnlyList<TransportKind> Order,
    bool FallbackOnlyBeforeFirstMessage = true);
```

- pi 的 `transport=auto` 优先 WebSocket，握手失败回退 SSE（Codex 语义）；
- **回退由协议层驱动**（它同时知道 HTTP 会话与 WebSocket 会话），不要强行把 WebSocket 塞进 `IStreamingHttpTransport`；
- `FallbackOnlyBeforeFirstMessage=true`：只允许在首个消息/首字节前回退；流已开始后失败直接报错，避免重复内容；
- 不支持的 kind/能力 → `TransportException(Unsupported)`，不静默降级。

## 11. 风险与开放问题

1. **UWR `SendWebRequest` 协程桥**：Host runner 的生命周期/取消语义需实机验证。
2. **gzip**：`ReceiveData` 是否已解压需抓包确认；若未解压，需解压层。
3. **IL2CPP**：`DownloadHandlerScript` 重写可能被剥离；必须 `link.xml`/`[Preserve]`。
4. **SseParser vendor**：需补 `ArrayBuffer.cs`，C# 11/12 语法降级；`Span`/`IAsyncEnumerable` 编译验证。
5. **代理**：UWR 仅系统代理；显式代理只能 HttpClient；能力声明必须诚实。
6. **HTTP/2**：2021.3 无；6.3+ UWR 可能默认 HTTP/2；只作为能力声明，不做版本分支。
7. **WebGL**：M2；`.jslib` + fetch；浏览器 CORS/无线程。
8. **许可证**：WorldTalk/江湖有灵/Yaolao/mikito 只参考模式，不复制代码；NativeWebSocket 按 Apache-2.0 处理。
9. **取消残留**：`Abort()` 后可能仍有回调；会话状态位必须丢弃。
10. **认证范围**：M1 只做 API Key；OAuth/SigV4 后置。
11. **WebSocket 实证边界**：`说书人测试/…/PerceptionWsClient.cs` 证明 `ClientWebSocket` 可在桌面 Unity netstandard2.1 连本地 `ws://`；但远程 `wss://`（TLS/代理/握手/keepalive）、IL2CPP、WebGL 未验证，M1 不承诺。**本地 ws 与远程 wss 必须作为两个支持等级分别验收。**
12. **签名最终化**：SigV4/ADC 必须在最终 header 上签名；UWR 若在发送后追加 header，必须禁用签名或改用 HttpClient。
13. **重试边界**：只在首字节前重试；流开始后绝不重试；401 刷新后最多重试一次。
