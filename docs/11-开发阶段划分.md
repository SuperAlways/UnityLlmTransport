# 11 · 开发阶段划分

> **依据**：`docs/10-架构设计.md`、`docs/09-参考项目评估矩阵.md`。
> **原则**：形状先行；每阶段有独立交付与门禁；先证明事实，再写生产代码；每阶段结束可独立验收。
> **日期**：2026-11-06

---

## 1. 阶段总览

| 阶段 | 目标 | 主要交付 | 门禁 |
|---|---|---|---|
| **0 · Spike** | 证明 Unity 事实与 vendor 可行性 | 事实报告 + go/no-go 决策 | 关键事实确认；不合并生产代码 |
| **1 · Core** | 纯 .NET 的接口、SSE、超时、重试、观测、Mock | `Abstractions` + `Sse` + 单测 | `netstandard2.1` 编译；纯 .NET 单测全绿 |
| **2 · UWR** | Unity 主路径真流式 | `UnityWebRequest` 传输 + Host runner + 主线程 | Unity Mono 实机：流式/取消/超时/溢出 |
| **3 · HttpClient** | 显式代理/TLS/桌面路径 | `HttpClient` 传输 + 代理/TLS 选项 | 桌面实机：代理/TLS/错误体 |
| **4 · Auth/集成** | 认证钩子与 PiUnityAgent 接入 | API Key/OAuth 注入、Finalizer、Retry/Deferred；一个 provider adapter 联调 | API Key + 401 refresh + mock provider 流 |
| **5 · 可选传输** | WebSocket/RawTcp/WebGL | WebSocket 实现、WS→SSE 回退、RawTcp 兜底、WebGL | 本地 ws、远程 wss、IL2CPP、WebGL 分别验收 |
| **6 · Hardening** | 发布质量 | 录制回放、背压/内存、telemetry、打包/文档 | 全矩阵 + Release 检查 |

---

## 2. 阶段 0 · Spike（事实确认）

**目标**：用最小实验回答“能不能做”，不写生产代码。

| 任务 | 内容 | 产出 |
|---|---|---|
| S0-1 | vendor `SseParser` 到 netstandard2.1：补 `ArrayBuffer.cs`、C# 11/12 语法降级、`IsExternalInit` | 编译报告 + 关键 parser 测试结果 |
| S0-2 | UWR `DownloadHandlerScript`：本地 SSE 服务，验证逐帧 `ReceiveData`、`gzip`、`Abort` 残留、`responseCode=0` | 事实报告 |
| S0-3 | 代理/TLS 矩阵：UWR vs HttpClient vs ClientWebSocket × 无代理/系统代理/显式代理 × 本地/远程 × 正常/自签 | 矩阵结果 + 错误分类 |
| S0-4 | WebSocket：`ws://127.0.0.1`、远程 `wss://`、IL2CPP 冒烟 | 支持等级结论 |
| S0-5 | IL2CPP：`DownloadHandlerScript` 重写、`link.xml`/`[Preserve]` | 构建/运行结论 |

**Go/No-Go**：

- UWR 真流式成立 → 进入阶段 2；
- UWR 逐帧/Abort 不成立 → 评估 HttpClient/RawTcp 作为主路径；
- `SseParser` 无法降级编译 → 自写最小 parser（保留 spec 测试）；
- 远程 wss 不成立 → WebSocket 仅本地/阶段 5 实验，M1 不承诺。

**门禁**：事实报告写入 `docs/`；不合并生产代码。

---

## 3. 阶段 1 · Core（纯 .NET）

**目标**：接口稳定、可单测、零 Unity 依赖。

| 任务 | 内容 |
|---|---|
| S1-1 | `Abstractions`：`IStreamingHttpTransport`、`ITransportSession`、`TransportRequest/Options/Headers`、`TransportCapabilities/Error` |
| S1-2 | `Sse` 包：vendor parser + 适配；SSE 边界测试 |
| S1-3 | `TimeoutTransport` / `TimeoutStream`：连接/首字节/空闲 |
| S1-4 | `MiddlewareTransport` / `IRequestMiddleware`；`TransportHeaders` 大小写/null 抑制 |
| S1-5 | `RetryTransport` / `IRetryPolicy` / `IAuthRefreshHandler`；只在首字节前重试 |
| S1-6 | `ITransportObserver` / `ObserverTransport`；`ITransportRequestFinalizer` |
| S1-7 | `ITransportSelector` / `TransportSelection` / `TransportFallbackPolicy` 形状 |
| S1-8 | `MockTransport` + 测试夹具（字节块、错误、慢速、取消） |

**门禁**：

- `netstandard2.1` 编译 0 错误；
- 纯 .NET 单测全绿（含 SSE 边界、header、超时、重试、取消、回退策略）；
- API review 通过；
- 无 .NET 6+ 专有 API。

---

## 4. 阶段 2 · UWR（Unity 主路径）

| 任务 | 内容 |
|---|---|
| S2-1 | `StreamingDownloadHandler`：`ReceiveData` 仅入队；有界 channel；溢出 abort |
| S2-2 | `ChannelReadStream`：`ChannelReader<byte[]>` → `Stream` |
| S2-3 | `UnityWebRequestTransport` / `Session`：请求组装、status/headers、错误体、Abort、Dispose |
| S2-4 | `IUnityWebRequestRunner`：协程桥、取消、主线程 |
| S2-5 | `Hosts.Unity`：主线程 dispatcher、生命周期 token |
| S2-6 | `link.xml` / `[Preserve]`；gitignore/packaging |
| S2-7 | 集成测试：本地 SSE mock + 真实端点；逐块/取消/空闲/溢出 |

**门禁**：

- Unity 2021.3 Mono 实机：真流式、取消、首字节/空闲超时；
- 主线程不做重解析；
- `responseCode=0` 错误分类正确；
- 无残留回调泄漏；
- IL2CPP 冒烟通过（若声明支持）。

---

## 5. 阶段 3 · HttpClient（代理/TLS/桌面）

| 任务 | 内容 |
|---|---|
| S3-1 | `HttpClientTransport`：`ResponseHeadersRead`、Stream、取消 |
| S3-2 | `ProxyOptions` / `TlsOptions` 映射：系统/显式代理、自签、客户端证书 |
| S3-3 | 重定向/压缩/错误体处理 |
| S3-4 | 错误分类与 `IsRetryable` 对齐 |
| S3-5 | 桌面测试：代理、自签、非 2xx、慢流、取消 |

**门禁**：

- 桌面实机：代理/TLS 矩阵通过；
- 不支持的能力显式 `Unsupported`；
- 与 UWR 输出同一 SSE 字节序列。

---

## 6. 阶段 4 · Auth / PiUnityAgent 集成

| 任务 | 内容 |
|---|---|
| S4-1 | `ApiKeyMiddleware`：options/env/store 优先级 |
| S4-2 | `OAuthTokenMiddleware`：只注入 token；刷新走 `IAuthRefreshHandler` |
| S4-3 | `ITransportRequestFinalizer`：SigV4/ADC/Azure AD 签名时序；能力声明 |
| S4-4 | Deferred 选项、目录刷新/图片/分类的传输形状 |
| S4-5 | PiUnityAgent.Ai 接入：一个 OpenAI-compatible provider adapter 使用 transport + SseParser；Faux/mock 端到端 |
| S4-6 | 401 → refresh → 重试；流开始后不重试 |

**门禁**：

- API Key 路径实机/集成通过；
- 401 refresh 后最多重试一次；
- SigV4 finalizer 单测（header 不被传输层改写）；
- PiUnityAgent 一个 provider 能通过 transport 产出 S2 事件（mock/真实端点）。

---

## 7. 阶段 5 · 可选传输

| 任务 | 内容 |
|---|---|
| S5-1 | WebSocket 实现：`ClientWebSocket` / NativeWebSocket；消息/Close/Keepalive |
| S5-2 | WS→SSE 回退：只在首消息前；流开始后不回退 |
| S5-3 | RawTcp 兜底：TcpClient/SslStream/HTTP1.1/chunked（仅当 UWR/HttpClient 都不可用） |
| S5-4 | WebGL：`.jslib` + fetch；M2 |
| S5-5 | 远程 wss / 代理 / IL2CPP / WebGL 矩阵 |

**门禁**：

- 本地 `ws://`、远程 `wss://`、IL2CPP、WebGL **分别**验收；
- 远程 wss 未通过则标“实验”，不写成支持；
- RawTcp 不作为默认路径。

**门禁**：

- 许可证/NOTICE 完整；
- 用户验收。

---

## 9. 依赖关系

```
S0
 ├─ S1 ── S2 ── S4 ── S5
 │        └─ S3 ── S4
 └────────────────── S6（贯穿）
```

- S0 必须先做；
- S1 可与 S0 部分并行（vendor parser 编译）；
- S2/S3 可并行（不同实现）；
- S4 依赖 S2（至少 UWR）与 S3（代理/TLS）；
- S5 依赖 S2/S4；
- S6 贯穿，最后收口。
